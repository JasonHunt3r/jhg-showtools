## 2. Correctness

### H1 (High) — FIXED. Undo survives a library switch and replays into the new library
`AppModel.update` and `applyRatings` register undo closures that capture show
and item **ids**. `switchTo(_:)` (AppModel.swift:121) never clears the
window's undo manager; nothing in the app calls `removeAllActions`.
Ids start at 1 in every library, so after File ▸ Open Library, ⌘Z finds the
*new* library's show with the same id and `saveShow`s the *old* library's
snapshot over it: name, defaults, overlays, collection id, and slides (the
slide upsert's `ON CONFLICT(id)` can also pull slides out of other shows).
Rating undo sets stars on whichever file has the same id. Foreign keys
only stop it when an id happens not to exist in the new library.
**Fix direction:** clear the undo manager in `switchTo` (the model needs a
way to reach it, or the view clears it on library change).

### H2 (High, plausible) — FIXED. The grid keeps the old library's thumbnails after a switch
`LibraryGridView` → `ForEach(visible)` keyed by item id → `ThumbnailView`
holds its picture in `@State` and reloads with `.task(id: item.id)`.
`switchTo` swaps libraries in one main-actor turn (`library = nil` then
`load`), so the grid never renders empty in between; the sidebar is
`.library` before and after, so the same `LibraryGridView` survives. Item
ids restart at 1 in every library, so tiles whose id exists in both keep
the *previous library's* picture under the new file name. Nothing
in the app ties view identity to the open library (no `.id(library)`).
Coming out of a **private** library, its pictures stay on screen in
the next one. The grid's `selection` (a set of ids) carries over too.
Related: `Thumbnails.load`/`strip` tasks already in flight when
`clear()` runs write the old library's images back into the cache under
ids the new library uses (AppModel.swift:121, Thumbnails.swift:16–53).
**Hands-on check:** two libraries with a few different photos each; view
the grid in one, File ▸ Open Library the other.
**Fix direction:** give the detail (or the whole main view) `.id(library root)`,
and a generation counter in `Thumbnails` so late loads are dropped.

### M1 (Med) — FIXED. Two imports can run at once
`importFiles` checks `importStatus` (AppModel.swift:200) but only sets
it after `await Ingest.collect` (line 202). A second drop or Import during
that await passes the check too. The two loops then interleave: the same file
in both gets copied twice (`name 2.jpg`), the second insert fails on the
unique hash, and **that copy stays in Media/ with no row** (see M2).
Also, once an import is running, a drop is silently ignored (returns `[]`):
a drop onto a show or collection during an import does nothing and says nothing.

### M2 (Med) — FIXED. A failed import can leave an unreferenced file in Media/
`copyIn` succeeds, then `lib.insertItem` throws (AppModel.swift:216): the
copy isn't removed. Nothing ever sweeps Media/ for files without a row.

### L1 (Low) — FIXED. `importProviders` stages inside the library root
`.staging-<uuid>` is removed by `defer`, but a crash mid-import leaves it
(and its copies of Photos originals) in the library folder for good.

### L2 (Low) — FIXED. A recent library that was deleted mid-session is recreated empty
Recents are filtered for existence only at launch. `openLibrary(at:)` →
`Library(root:)` creates the folders, so picking a since-deleted entry
from Open Recent silently makes a new empty library there. Open Library…
checks for `Library.sqlite`; Open Recent doesn't.

### L3 (Low) — FIXED. Renaming a library for Spotlight drops it from Open Recent
`setSpotlightIndexing` moves the folder but doesn't update `recentLibraries`.
The old path is filtered out at next launch and the new one is never added.

### L4 (Low) — FIXED. A drop that mixes in-app items with Finder files loses the Finder files
`ItemDrag.ids(from:)` returns only our ids when any provider is ours.

### M3 (Med, measured) — FIXED. Short slides: two transitions overlap and a picture pops out
`ShowTimeline.init` fits leads in the order 1, 2, … n−1, then 0, then 1
again (Timeline.swift:215–217). Re-fitting slide 1 can shrink its lead, which
lengthens its transition's tail past the join, but slide 2 was already fitted
against the old, shorter tail and isn't checked again.
Measured through ShowToolsCore (probe in the scratchpad), non-looping show,
new-show default (2 s dissolve, lead 1), slides 2.5 / 2.2 / 5 s:
```
slide 1  in: runs 2.00…4.00      slide 2  in: runs 3.70…5.70   ← overlap
t=3.6  0→1 p=0.80
t=3.7  1→2 p=0.00                 ← slide 0 (still ~15% visible) vanishes in one frame
```
Only shows with slides shorter than about 3 s. At the 5 s default it can't happen.
Two smaller things in the same code:
- In a show that **doesn't loop**, slide 0's transition in never plays, but its
  tail still counts against slide 1's room, so slide 1's lead is cut for
  nothing (0.5 instead of 1 above).
- Fitting rule is sound once it's a fixed point; iterating `fitLead` until
  nothing changes (or fitting 0 first, from the last slide's raw values)
  would fix both. **Needs a test** in TimelineTests either way.

### L5 (Low) — FIXED. Right-click ▸ Play on an empty show opens a black player
The Show menu's Play is disabled for a show with no slides; the sidebar's
context-menu Play and Play Full Screen (MainView.swift:163) aren't.
Harmless (the timeline returns `.empty`), just a black window.

### M4 (Med, plausible) — FIXED. Bare-key shortcuts in Edit Show may eat typing
Edit Show registers J, K, L and ⇧Z as hidden buttons with
`.keyboardShortcut(…, modifiers: [])` (EditShowView.swift:135–140), and
Play/Pause on **space** (line 514). SwiftUI turns these into window key
equivalents, and AppKit offers key equivalents to the window before the
focused text field. Edit Show has text fields: the Collection Browser's
Search, the Effects number boxes, the lane's fade SecondsFields.
**Hands-on check:** click into the Collection Browser's Search and type
"jelly", or a space. If the playhead shuttles or play toggles and the
letters don't appear, this is real.
**Fix direction:** handle J/K/L/space in the canvas/storyline's own
`keyDown` (as the player window already does) instead of as shortcuts.

### M5 (Med) — FIXED. Typing a show name makes one undo step and one save per keystroke, and allows an empty name
DefaultsBar's name field (ShowView.swift:244) binds straight to
`mutate("Rename Show")`, so renaming to "Holiday" is 7 undo steps and 7
database writes, and deleting all the text saves a show called "". The
sidebar's Rename… goes through `renameShow`, which refuses an empty name.
That breaks the CLAUDE.md rule that an edit is one undo step.

### L6 (Low) — FIXED. Hover cursors are pushed/popped in pairs that can come unbalanced
`NSCursor.push()` on hover-in, `pop()` on hover-out: EditShowView.swift:233
(strip bar), StorylineView.swift:337–340 (trim zones, which move while
you drag), KenBurnsEditor.swift:129. If the view goes away or moves out from
under the pointer without a hover-out, the cursor stays as a resize arrow
until something else pops it. The usual fix is `.pointerStyle` (macOS 15)
or an `onContinuousHover` that sets rather than pushes.

### L7 (Low) — FIXED. "Place Image Here…" skips the collection rule
`LibraryPicker` offers the **whole library** (`model.items`, ImagesRow.swift:244)
and `place` never calls `bringIntoCollection`. A file outside the show's
collection can go into the lane without the "isn't in the collection, add
it?" question that every other way in asks. (Drops onto the row do ask.)

### L8 (Low) — FIXED. Dropping several files on the images row stops at the first video
`place` uses `break` (ImagesRow.swift:105) both for "no room left" and for
"this one's a video", so a video in the middle of a drop means nothing
after it is placed, although there's room.

### L9 (Low) — FIXED. A Transform or Rotation drag in progress is dropped if the preview goes away mid-drag
`TransformOverlay.onDisappear` commits only a nudge run (`commitRun` skips
when `drag != nil`) and ends the live edit. Switching mode or show while
dragging loses the change silently. Hard to do by accident.

## 4. Real-library safety

- `~/Pictures` has **no ShowTools library** today, so nothing real can be damaged yet.
- Tests use temp folders. The iCloud test is refused before anything is
  created. `stcli` needs an explicit path. `make-test-library.sh` only removes
  `<dir>/TestLib.noindex`. **All safe.**
- **Gap:** the app falls back to the real master whenever `SHOWTOOLS_LIBRARY`
  is missing or empty (Library.swift:22). A typo in the `open --env` line, or
  a dev hook without it, opens (and creates or migrates) `~/Pictures/ShowTools Library.noindex`.
  Suggestion: make any `SHOWTOOLS_DEV_*` variable without `SHOWTOOLS_LIBRARY` refuse to launch.
- **Gap:** "The master library upgrades itself on first open" with no backup.
  Once real photos are in it, a bad migration is permanent. Suggestion:
  checkpoint the WAL and copy `Library.sqlite` to `Library.sqlite.v<N>.bak`
  before any migration runs.
- Opening the app normally always opens (so creates) the master before
  File ▸ New Library… can be chosen. The handoff's "so the master isn't
  touched" means *used*, not *created*.
- `defaults` for `com.jhg.showtools` are shared by test and real runs
  (`editMode`, column widths, Open Recent). Harmless, but a scratch library
  opened in a test run will show up in the real Open Recent.

## 5. Docs vs code

- **CLAUDE.md and handoff line 109 say every model type decodes field by field.**
  `KenBurnsFrame`, `ImagePoint` and `SRGBColor` are still synthesized. They're
  small and stable, but adding a field to any of them would drop every saved
  Ken Burns move, pivot or background that lacks it. Either convert them
  or narrow the claim.
- **A trap the docs don't mention:** `Transition.init(from:)` *requires* `style`,
  so removing or renaming a `TransitionStyle` case (as Accordion was dropped)
  turns every saved transition of that style back into the show default,
  permanently on the next save. The same goes for any enum case removed from `Fit`,
  `BlendMode`, `Easing`, `Direction`. Worth one line in the rules.
- **"Each migration tested by opening a library written by the version before":**
  there are real old-version tests for v1→(all) and v3→4. v2→3 and v4→5 are only
  run as part of those chains, never from a genuine v2 or v4 file. Close enough, but
  the claim is stronger than the tests.
- Handoff's test count (70), schema version (5), dev hooks, known debts, and
  the "preview only updates on release" note all match the code.

## Fixes (2026-09-21, same day)

- **H1:** `AppModel.libraryGeneration` is bumped on every library load. Undo
  steps (show edits and ratings) do nothing if it has changed, and MainView
  clears the window's undo history when it changes. Side effect: the Spotlight
  rename reopens the library, so it clears undo too (harmless).
- **M3:** leads are re-fitted until nothing moves, and slide 0's unplayed
  transition in a non-looping show takes no room. New tests in
  `TransitionLeadTests` (they fail on the old code, pass now). The probe
  case now gives both dissolves their full 2 s, centred, with slide 1
  alone between 3.5 and 3.7 s. Shows with short slides will time slightly
  differently: that's the fix.
- **M1:** imports queue: each waits for the one before, so none is dropped
  and none runs alongside another. Each import is tied to the library
  that was open when it was asked for, and does nothing (returns no ids) if
  that library has been closed since.
- **M2:** if the database row can't be written, the copy is removed from Media/.
  (`stcli ingest` has the same pattern and wasn't changed.)

**Hands-on (Claude can't click):**
- H1: edit a show, Open Library another, check Edit ▸ Undo is empty.

badge) start drag tracking: only a row's empty edges selected it (Jason: "the

the app's defaults; ⌘Q/willTerminate and SIGTERM remove it. A plain launch
that finds a note from a pid no longer running refuses to open a library,
says why, and clears the note (so it refuses once). Four unit tests (81).
Checked live: a test copy's note appears, `kill` removes it with no crash
report; with a dead copy's note in place, a plain launch showed "Library
problem: The last test copy … didn't quit normally…" and created nothing
in ~/Pictures.
